## 0. 冻结与修订规则

本方案的作用是让"结论"与"口径"分离：数据可以说话，但口径不能事后调整。

1. 方案冻结后，**研究问题、样本纳入排除规则、人工评分流程、指标口径**四项不得修改。
   实验执行中若发现方案有缺陷，**不改方案**，而是把它写进实验记录的"威胁与局限"一节。
2. 确需修订时，修订必须单独成文、注明日期与理由，并重新执行一遍实验。
   用不同口径跑出来的两组数字不得混在同一张表里比较。
3. 实验记录中引用的每一个数字，都必须能追溯到本方案的一条规定、一条命令和一份归档文件。

## 1. 研究问题

三个问题都写成可被数据证伪的问句。**不预写目标数值**，也不预设"系统有效"。
结果与预期相反同样如实记录——一个被证伪的假设比一个含糊的正面结论更有价值。

### RQ1：模型建议分与教师最终分的偏差有多大？

在 100–300 条真实、匿名的初中数学解答题作答上，AI 建议分与教师最终分的
**平均绝对误差（MAE）**、**完全一致率**、**1 分容差命中率**分别是多少？

**证伪条件**：若三项指标无法与"模型建议分直接取满分"或"直接取零分"这类
平凡基线拉开差距，则本问题得到否定结论。

### RQ2：错因分类的质量如何？

七类错因上的**宏平均 F1**、**逐类 F1**、**主要混淆方向**是什么？

**证伪条件**：若宏平均 F1 与"全部预测为出现频率最高的那一类"这一基线相当，
则说明模型未提供有效的错因区分能力。

### RQ3：教师如何使用模型建议？

教师的**采纳 / 修改 / 驳回**比例分别是多少？教师与模型的**平均耗时与中位耗时**
差异如何？

**证伪条件**：若采纳率与随机一致率无法区分，或模型耗时不低于教师耗时，
则"分担教师负担"的说法不成立。

> 三个问题共用同一份样本。为保证可比，**RQ1–RQ3 必须由同一次导出、同一次评测产出**，
> 不得为了某个问题单独挑选样本。

## 2. 样本纳入与排除规则

### 2.1 纳入条件（全部满足才计入）

| # | 条件 | 理由 |
|---|---|---|
| 1 | 来自**真实班级**的真实作业 | 演示数据与构造数据不能回答"真实场景下表现如何" |
| 2 | 题型为**解答题** | 客观题由规则评分直接判定，不涉及模型判断 |
| 3 | 该样本的**模型任务成功完成** | 调用失败或超时的样本没有模型建议可比 |
| 4 | 该样本**已被教师复核** | 没有教师最终判定就没有真值 |
| 5 | **模型原始错因存在**（`ai_error_type` 非空） | 缺失则无法构成可比较的一对 |

### 2.2 排除条件（命中任一即剔除）

- 演示 / 构造数据；
- 客观题的规则评分结果；
- 仍处于**待复核**状态的样本；
- **身份字段未完成脱敏**的文件（整份文件作废重做，不是逐行剔除）；
- 缺失 `ai_error_type` 的、本次迁移之前生成的历史行——这类样本的教师复核已经覆盖了
  `error_type`，但模型当初判成什么无法还原。**不猜、不补**，剔除并在记录中写明条数。

### 2.3 部分缺失不等于剔除整行

`teacher_seconds`、`ai_seconds`、`input_tokens`、`output_tokens`、`model_name`、
`prompt_version` 属于**可选列**。某一列缺失时：

- **该行仍然计入样本量与评分、分类指标**；
- 只在对应统计量中排除该行，并在实验记录里写明缺失条数；
- 不把缺失读成 0——空单元格不会被算进平均值，整列为空时输出 `null` 而非 `0`。

用时超限（超过 1 小时）、负数或非数字会被服务端按**缺失**记录并留一条警告，
不阻断教师复核。这类样本同样只在用时统计中排除，条数必须写进实验记录。

`teacher_modification_rate` 与 `review_decision_rate` 由同一列推导，读取时交叉校验
`teacher_modified == (review_decision != "ACCEPT")`，不一致直接报错而不是静默取一个值。

## 3. 样本获取与脱敏

### 3.1 获取方式

不手工整理。教师在系统里复核完一份作业后，逐份调用导出接口：

```text
GET /api/evaluation/assignments/{assignmentId}/grading-cases.csv
```

按 `assignmentId` 升序逐份导出，追加到同一份 CSV（保留一份表头）。
导出物即评测脚本的输入契约，列名与 `evaluation/README.md` 一致，可直接作为 `--grading` 参数。

### 3.2 三件必须记录的事

响应头给出导出完整性的三个计数，**每次导出都要抄进运行日志**：

| 响应头 | 含义 |
|---|---|
| `X-Evaluation-Reviewed` | 该作业中教师已复核的样本总数 |
| `X-Evaluation-Exported` | 实际写进 CSV 的行数 |
| `X-Evaluation-Skipped-Missing-Ai-Error` | 因缺少模型原始错因被剔除的行数 |

**CSV 文件本身看不出少了行。** 只记 `X-Evaluation-Exported` 会把导出条数当成样本量，
所以三个数都要落在日志里，占位痕迹才不会丢。

### 3.3 人工脱敏检查（导出后必做）

接口不输出姓名、学号、班级、学校，但**文件带出受控环境前必须再人工核对一遍**：

- 确认 `case_id` 形如 `answer-{主键}`，不含任何身份字段；
- 确认没有多导出列、没有把身份信息塞进备注类字段；
- 确认身份映射表**不在**归档目录内，也不在任何提交进 Git 的路径下。

映射表单独保存在受控位置，谁执行脱敏、何时执行、表存在哪里，写进实验记录。
模型请求与导出物都不得包含姓名、学号、班级名、学校名、JWT、模型密钥或身份映射表。

## 4. 人工评分与偏差控制

### 4.1 评分人

- 至少**一名合作教师**，依据题库中的评分项独立给出**最终分**与**最终错因**；
- 记录评分人的教龄，以及是否参与过本系统设计——参与设计的人容易对模型输出更宽容，
  这一点必须在局限性里写明。

### 4.2 顺序与可见性（防锚定）

1. 教师**不得在录入人工真值前看到任何汇总指标**，包括本方案提到的 MAE、F1、采纳率；
2. 教师按**打乱后的顺序**评分，避免模型建议的排列顺序形成锚定；
3. 模型建议与教师判定**分别录入**，教师判定一旦提交不再回改；
4. 记录分歧时**不使用模型输出参与裁决**——模型输出是被检验对象，不能当裁判。

### 4.3 单评与双评

| 情形 | 处理 |
|---|---|
| **只有一名教师** | 论文必须把**单评偏差**明确列为限制，不得回避 |
| **有两名教师** | 先各自独立评分，再记录分歧裁决过程与裁决依据；报告双评一致性 |

### 4.4 用时口径

教师用时由前端计时：从教师选中该待复核项开始，到提交复核为止，
被挂起或离开页面的时间**一并计入**。这一口径与实际备课场景的差距，写进局限性。

用时同时报**均值与中位数**：中位数明显低于均值时，说明均值被少数离群样本抬高，
此时**不得单独引用均值**。

## 5. 归档布局

归档目录在**仓库之外**，`git add` 不能碰到它：

```text
E:\homework-analysis-experiment-archive\2026-09-main-study\
  protocol\论文正式实验方案.md
  input\grading-cases.csv
  input\error-labels.csv
  output\metrics.json
  logs\run.txt
  checksums\sha256.txt
```

| 路径 | 内容 | 来源 |
|---|---|---|
| `protocol\论文正式实验方案.md` | 本文件的副本 | `docs/experiments/2026-09-15-论文正式实验方案.md` |
| `input\grading-cases.csv` | 冻结的匿名样本 | 3.1 节的导出结果合并而成 |
| `input\error-labels.csv` | 冻结的标签全集 | `evaluation/data/error_labels.example.csv` 的副本 |
| `output\metrics.json` | 评测指标 | 5.3 节的命令产出 |
| `logs\run.txt` | 运行日志 | 见 5.4 |
| `checksums\sha256.txt` | 三个文件的哈希 | 见 5.2 |

**副本而非符号链接**：目录要能整体拷贝给答辩委员会或导师，
链接换一台机器就断，副本不会。

### 5.1 建立目录

```powershell
$experimentRoot = 'E:\homework-analysis-experiment-archive\2026-09-main-study'
'protocol','input','output','logs','checksums' | ForEach-Object {
  New-Item -ItemType Directory -Force -Path "$experimentRoot\$_" | Out-Null
}
```

### 5.2 哈希（三个文件都要算）

```powershell
$experimentRoot = 'E:\homework-analysis-experiment-archive\2026-09-main-study'
Get-FileHash "$experimentRoot\input\grading-cases.csv"  -Algorithm SHA256
Get-FileHash "$experimentRoot\input\error-labels.csv"   -Algorithm SHA256
Get-FileHash "$experimentRoot\output\metrics.json"      -Algorithm SHA256
```

把三条输出**原样存进** `checksums\sha256.txt`。哈希是"论文引用的到底是哪一份输入"
的唯一凭据：输入改了，指标就不再是同一批数据算出来的。

### 5.3 运行评测

```powershell
$experimentRoot = 'E:\homework-analysis-experiment-archive\2026-09-main-study'
python evaluation/evaluate_grading.py `
  --grading "$experimentRoot\input\grading-cases.csv" `
  --labels  "$experimentRoot\input\error-labels.csv" `
  --output  "$experimentRoot\output\metrics.json"
```

**必须显式传 `--labels`。** 不传时会退化成"样本里实际出现过的标签"，
换一份样本标签集合就变了，宏平均 F1 的分母随之改变，两批数据就不可比。
指标口径的完整说明见 `evaluation/README.md`。

### 5.4 日志内容

`logs\run.txt` 至少包含：

- 执行时间、操作系统、Python 版本；
- 3.2 节逐份导出的三个响应头计数（复核总数 / 实际导出 / 缺失原始错因剔除数）；
- 5.2 节的三条哈希；
- 5.3 节的完整命令与脚本的标准输出；
- 教师用时被记为空（超限/负数/非数字）的条数。

日志里**不得**出现姓名、学号、班级名、学校名、令牌或密钥。
导出接口不做日志输出，这类信息要出现只能是手工粘贴进去的——不要粘。

### 5.5 仓库外的原因

真实匿名样本、真实结果 JSON 与身份映射表**一律不提交进 Git**。
仓库可能被克隆、被 fork、被公开，提交进去就收不回来。
仓库里只保留脚本、契约文档和构造的示例数据。

## 6. 复现与记录

- 评测脚本只用 Python 标准库，可在**离线环境**重跑，不需要联网、不需要安装依赖；
- 同一份输入永远得到同一份 `metrics.json`（数字保留 6 位小数，消除浮点尾数）；
- 实测记录写进 `docs/experiments/` 下独立的记录文件，模板见
  `docs/experiments/2026-09-14-实验记录模板.md`；
- 记录中的指标从 `metrics.json` **逐项抄录**，不重新计算、不修约。

## 7. 本方案不覆盖的范围

写清楚"没验证什么"，避免结论被过度解读：

- 不涉及学生端、家长端、管理员端；
- 不涉及在线考试、拍照识别（OCR）、题库检索增强（RAG）或向量数据库；
- 不评估知识点画像与分层练习的教学效果——本次只评估**评分与错因判定**；
- 不评估系统在高并发、多校部署下的工程性能；
- 样本仅覆盖纳入范围内的题型与知识点，结论**不外推**到其他学段、其他学科。
