# 实验记录模板

> **使用说明**：本文件是模板，不是实验记录。复制为 `YYYY-MM-DD-<实验名>.md` 后再填写。
> 所有数字必须来自实际运行，**不得预填估计值、示例值或"预期效果"**。
> 尚未取得数据的章节写"待补"，不要留空，也不要写占位数字——
> 占位数字最容易被后来的人当成真实结果引用。
>
> 论文里引用的每一个数字，都应能追溯到本文件的一行命令和一份归档结果。
>
> **正式实验的口径已经冻结**，见 `docs/experiments/2026-09-15-论文正式实验方案.md`。
> 研究问题、样本纳入排除规则、人工评分流程、指标口径四项按方案执行，不在记录里临时调整；
> 方案确有缺陷时，写进第 9 节"威胁与局限"，不改方案。

## 2. 样本来源与脱敏方式

| 项 | 内容 |
|---|---|
| 样本来源 | 哪个班级、哪份作业、哪次考试；采集时间范围 |
| 抽样方式 | 全量 / 随机抽样 / 分层抽样；抽样依据与随机种子 |
| 样本量 | 学生作答条数、题目数 |
| 题目类型构成 | 客观题、解答题各多少 |
| 满分分布 | 各分数档的题量 |

**样本如何取得**：不必手工整理。教师在系统里复核完一份作业后，用导出接口取样本：

```text
GET /api/evaluation/assignments/{assignmentId}/grading-cases.csv
```

导出物只含匿名编号，列名与 `evaluate_grading.py` 的输入契约一致，可直接作为 `--grading` 参数。
导出规则、被剔除的样本如何计数，见 `evaluation/README.md`。

**脱敏处理**：

- 姓名、学号、班级、学校如何替换为匿名编号；
- 编号与真实身份的对照表存放在何处（**不进入本仓库**）；
- 模型输入中是否包含任何身份信息（本项目要求：不包含）；
- 谁执行脱敏、何时执行。

被挂起或离开页面的时间会一并计入——这与"是否包含被打断的时间"必须写清楚，
并且要说明超限值被记为空（见 `evaluation/README.md` 的用时口径说明）。

## 5. 实验参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 容差 | | 评测脚本 `--tolerance`，默认 1 分 |
| 标签全集 | | 冻结的 `error_labels` 文件路径及其 SHA-256 |

标签全集必须与后端 `ErrorType` 一致：模型能用的六项，另有规则评分产生的

换了标签全集，宏平均 F1 的分母就变了，前后两批数据不可比。

## 6. 运行命令与归档

### 6.1 样本导出记录

逐份作业导出，每次都要抄下响应头给的三个计数。**CSV 文件本身看不出少了行**，
只记实际导出条数会把导出量当成样本量。

| 作业 ID | 复核总数 `X-Evaluation-Reviewed` | 实际导出 `X-Evaluation-Exported` | 缺失原始错因剔除 `X-Evaluation-Skipped-Missing-Ai-Error` |
|---|---|---|---|
| | | | |
| **合计** | | | |

**导出后的人工脱敏检查**：是否已逐列确认不含姓名、学号、班级、学校？身份映射表存放位置（不在本仓库）？

### 6.2 命令

```powershell
# 实际执行的命令，原样粘贴，不要改写
python evaluation/evaluate_grading.py `
  --grading <匿名样本路径> `
  --labels <冻结的标签全集路径> `
  --output <结果路径>
```

`--labels` **必须显式传**。不传时会退化成"样本里实际出现过的标签"，
换一份样本标签集合就变了，宏平均 F1 的分母随之改变，两批数据不可比。

### 6.3 归档

| 项 | 内容 |
|---|---|
| 执行时间 | |
| 执行环境 | 操作系统、Python 版本 |
| 归档根目录 | 仓库之外的受控路径 |
| 样本文件哈希 | `input\grading-cases.csv` 的 SHA-256 |
| 标签文件哈希 | `input\error-labels.csv` 的 SHA-256 |

三个文件都要算，只算结果文件不够。

**以下字段从结果 JSON 逐项抄录，不要重新计算，也不要修约。**

### 7.1 评分误差与错因分类

### 7.2 复核决策三项比例

| 指标 | 数值 |
|---|---|
| 采纳率 `accept` | |
| 修改率 `modify` | |
| 驳回率 `reject` | |
| 教师修改率 `teacher_modification_rate` | |

`teacher_modification_rate = modify + reject`，它是**旧口径的一致性检查，不是第四种决策**。
三项比例之和恒为 1，与旧口径对不上说明导出环节改坏了其中一列——
这种情况会被读取时的一致性校验直接挡下，不需要人工核对。

### 7.3 溯源与缺失

| 指标 | 数值 |
|---|---|
| 模型名集合 `provenance.model_names` | |
| 提示词版本集合 `provenance.prompt_versions` | |
| 缺模型名的条数 `missing_model_name_count` | |
| 缺提示词版本的条数 `missing_prompt_version_count` | |
| 各可选列缺失条数（用时、令牌逐列记） | |

缺失一律留空，**不得用某个模型名或版本号顶上**。集合里有几个元素，
就说明这批样本跨了几个模型或几个提示词批次——跨批次会削弱结论强度，必须写进局限性。
缺失条数要落在报告里：这些样本没有静默消失，只是不进对应统计量。

| 指标 | 数值 |

## 9. 威胁与局限

- **样本量**：是否足以支撑结论；置信区间有多宽；
- **样本代表性**：只覆盖了哪些题型、哪些知识点，结论不能外推到什么范围；
- **评分人偏差**：单评还是双评；教师是否受模型建议影响；
- **标签主观性**：哪些错因标签之间存在天然歧义；
- **用时口径**：计时方式与实际备课场景的差距；
- **未验证项**：本次实验**没有**验证什么，明确写出来，避免被过度解读。

---

## 10. 结论

用一句话回答第 1 节提出的每个研究问题。结论强度必须与证据强度匹配——
样本量小、只覆盖一个班级时，写成"在本样本范围内观察到……"，不要写成"系统能够……"。
