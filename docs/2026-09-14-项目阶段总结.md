# 初中数学作业分析系统阶段总结

## 一、课题定位

课题名称建议使用：**基于知识点画像与大模型辅助反馈的初中数学作业分析系统设计与实现**。

系统面向初中数学教师，解决结构化答案批量整理、客观题自动评分、解答题过程性反馈、教师复核和学情统计相互割裂的问题。项目不追求让大模型代替教师，而是采用“确定性规则 + 大模型建议 + 教师确认”的人机协同路线。

## 二、当前已经形成的完整闭环

```text
教师登录与数据隔离
        ↓
班级、学生、知识点和题库维护
        ↓
创建作业并导入 Excel 答案
        ↓
客观题规则评分 / 解答题 AI 建议
        ↓
教师采纳、修改或驳回
        ↓
按已确认结果生成知识点画像和错因统计
```

当前代码已覆盖以下功能：

- JWT 登录、BCrypt 密码校验和教师数据隔离；
- 班级与学生名册管理；
- 七至九年级知识点、题库、可接受答案和过程评分项；
- 作业创建与 `.xlsx` 答案导入；
- Excel 表头、公式单元格、未知编号、重复答案和整批回滚校验；
- 单选题、填空题的确定性规则评分；
- 解答题 AI 任务、Responses 风格模型适配器、JSON Schema 结构化输出校验和有限重试；
- 教师采纳、修改、驳回以及复核审计；
- 只基于已确认结果的知识点掌握度和高频错因统计；
- Vue 中文教师端、演示数据、响应式布局和主流程浏览器测试。

## 三、当前技术实现

| 层次 | 当前实现 |

## 五、当前最有价值的部分

1. **需求真实**：教师确实需要批量处理作业、定位共性错因并保留人工最终决定权。
2. **技术组合合理**：传统规则负责确定性内容，大模型只处理开放性解答，避免把所有问题都交给模型。
3. **师范特色明确**：知识点画像、过程评分、错因反馈和教师复核都直接对应教学评价过程。
4. **论文可实验**：可以比较 AI 建议与教师评分之间的误差、错因识别效果、教师修改率和节省时间。
5. **边界适合毕设**：不增加 RAG、OCR、学生端和微服务，工作量可控，核心创新点仍然成立。

- 当前仓库尚未产生正式提交，所有新增文件仍需在最终交付前统一审查。

## 九、第二轮补充：论文取数能力与真实模型验证

验证日期：2026 年 9 月 15 日（晚于第八节）。这一轮做的不是新功能，
而是把"论文要引用的数字从哪来"这条路打通：此前评测脚本的输入只能靠手工整理，
系统里也没有任何地方记录模型耗时、令牌用量和教师复核耗时。

### 9.1 补上的取数字段（Flyway V7）

`grading_result.ai_error_type`、`ai_grading_task.input_tokens / output_tokens / ai_seconds`、
`teacher_review.teacher_seconds`。全部可空。

其中 `ai_error_type` 是必需的：教师复核会覆盖 `grading_result.error_type`，
覆盖之后模型当初判成什么就再也查不回来，而"错因一致率"正是要评测的指标之一。

模型耗时只量一次 HTTP 交换（解析与校验不计入）；用量取自响应体的 `usage` 块，
缺失时记 null 而不是 0——"没有数据"和"没花令牌"混在一起会让统计失真。

### 9.2 取数路径

教师界面在选中待复核项时开始计时（`performance.now()`，单调时钟，不受系统对时影响），
确认时把秒数随复核请求提交。取数用新增的导出接口：

```text
GET /api/evaluation/assignments/{assignmentId}/grading-cases.csv
```

导出的是**已复核的模型评分样本**，列名与 `evaluation/evaluate_grading.py` 的输入契约一致，
可原样喂给脚本，不需要任何手工整理。接口按作业归属鉴权，导出物只含匿名编号。

评测脚本新增中位数口径（`teacher_median_seconds`、`ai_median_seconds`）。
加它的原因是用时分布不对称：教师中途去忙别的事会留下一个几十分钟的离群值，
把均值整体拉高，而中位数不受影响。两个口径并列输出，均值有没有被带偏一眼可见。
原有的 `estimated_saving_ratio` 仍按均值计算，没有改口径，避免同一个数字在论文前后不一致。

### 9.3 同时修复的两个缺陷

- **演示配置把环境变量彻底压掉**：`application-demo.yml` 里写死的 `app.model.*` 字面量
  优先级高于 `application.yml` 的 `${MODEL_ENABLED:...}` 占位符，
  导致按文档设置 `MODEL_*` 环境变量后仍然走"模型未启用"分支，
  失败还在 0.1 秒内返回，看起来像网络问题。改为 profile 只提供默认值、覆盖入口留给环境变量。
- **失败原因被吞掉**：`AiGradingTaskWorker` 把所有异常统一映射成同一条对外消息，
  却不记录 cause，配置错误、连接失败与响应解析失败在外部完全无法区分。
  现在按任务记录一条 WARN（含异常链），异常链不含密钥与响应体。

## 十、第三轮补充：教师端公式渲染与 Word 公式降级

验证日期：2026 年 9 月 15 日（晚于第九节）。这一轮解决的是一个被长期搁置的
显示问题：数学题干、学生作答和评分说明里的 `$...$` 一直按原文显示，教师看到的是
`$2x+1=5$` 而不是 `2x+1=5`；导出的 Word 同样把公式当普通文本，`\angle` 这类命令
直接以反斜杠形式印在纸上。

### 10.1 前端：只渲染，不执行

题干、作答与评分说明一律仍以 UTF-8 纯文本入库，**不保存用户 HTML**，
也不新增数据库迁移。渲染发生在显示层：

- `frontend/src/math/segments.ts` 只识别 `$...$`（行内）与 `$$...$$`（独立成行）；
  `\$` 转义、未闭合的 `$`、空公式，以及不满足空白/数字边界的输入一律降级为纯文本，
  不会出现“算式被吃掉一半”的情况；
- `frontend/src/math/render.ts` 是**全项目唯一**引入 KaTeX 的源文件，
  固定使用 `{ throwOnError: false, strict: false, output: 'htmlAndMathml' }`。
  `output` 选 `htmlAndMathml` 是为了让公式同时带 MathML，屏幕阅读器能读出来；
- 用户文本段只走 Vue 文本插值（`MathText.vue` → `MathSegment.vue`），
  没有任何 `v-html`，公式源码本身不被当作 HTML 解析。

接入的五处教师端字段：

| 页面 | 字段 |
| --- | --- |
| 数学题库 | 题干 `content` |
| 分层练习 | 题目正文 `content` |
| 教师复核 | 题干 `questionContent` |
| 教师复核 | 学生作答 `answerContent`（未作答时显示“（未作答）”） |
| 教师复核 | 教师评语 `teacherExplanation` |

KaTeX 的 CSS 在 `frontend/src/main.ts` 全局引入一次；KaTeX 本体落在按路由懒加载的
公共分块里（`MathText-*.js`），主包不受影响。

### 10.2 后端：Word 只转换明确的 Unicode 子集

`backend/.../exercise/LatexToUnicode.java` 是一个单趟扫描的确定性转换器，
刻意不用正则替换——只有单趟扫描才能保证转义先于上下标处理、`\frac` 按平衡括号取参数。

- **命令表**（共 18 个）：`\angle`→∠、`\parallel`→∥、`\perp`→⊥、`\triangle`→△、
  `\odot`→⊙、`\sim`→∽、`\cong`→≌、`\times`→×、`\div`→÷、`\pm`→±、`\cdot`→·、
  `\leq`/`\le`→≤、`\geq`/`\ge`→≥、`\neq`/`\ne`→≠、`\approx`→≈；
- `\left` / `\right` 直接删除（它们只影响排版，删掉不丢信息）；
- `\frac{a}{b}` → `a/b`，`\sqrt` → `√`；
- 上下标按 Unicode 上标/下标表逐字符转换（`0-9`、`+ - = ( )`，以及 `n i` / `i j`）；
- `\angle`、`\triangle`、`\odot` 是“前缀命令”，`\angle 1` 转成 `∠1` 而不是 `∠ 1`；
- 命令表以外的命令（如 `\begin{cases}`、`\vec`）**不做猜测**：保留公式源码原样，
  返回 `fellBack=true`，由调用方标红并收集题号。

转换范围刻意收得很窄。这不是缺陷而是取舍：宁可让教师看到一眼能认出的
`\begin{cases}` 源码，也不要自动猜成一个可能错误的符号——数学式子转错了，
比没转更糟。

### 10.3 降级如何报到教师眼前

导出响应新增 `X-Formula-Fallback` 头，按题目在文档中出现的顺序去重，
最多返回 20 个题号，超出部分追加 `...`。响应体仍是原来的 DOCX 字节流，
用响应头传降级信息是为了不破坏既有下载链路。

对应的文档内表现：只有降级公式所在的那个 run 被标成红色（`CC0000`），
同一段落里的其他 run（题号、分值、知识点、标准答案标签）保持黑色。

前端在下载成功后同时弹两条提示：先 `已开始下载 Word 文档`，
再在存在降级时警告 `这些题目的公式没能完整转成 Word 格式，文档中已标红：<题号>`。
红色标记只在 Word 里看得见，不在页面上点名，教师打印前不会知道要核对哪几道题。

### 11.5 一个值得记下的环境坑

在 Windows + Git Bash 下启动后端时，Git Bash 会把以 `/` 开头的环境变量值改写成
Windows 路径。`MODEL_API_PATH=/v1/responses` 到 JVM 里变成了
`D:/git/Git/v1/responses`，`RestClient` 建 URI 时抛出
`IllegalArgumentException: invalid URI scheme d`，一次试运行的 40 次调用全部失败，
而异常信息里看不出任何与路径有关的信息。

规避方式是启动脚本里显式 `unset MODEL_API_PATH`——`application.yml` 中该值默认就是
`/v1/responses`，不设比设法安全：只要环境里存在这个变量，就有被改写的风险。
