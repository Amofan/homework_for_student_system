# 基于知识点画像与大模型辅助反馈的初中数学作业分析系统设计方案

## 1. 项目概述

本项目面向初中数学教师，设计并实现一套作业分析与分层教学辅助系统。系统通过确定性规则完成客观题批改，通过大模型对解答题提供分步评分建议、错因标签和反馈建议，再由教师审核确认。教师确认后的数据用于生成班级知识点掌握情况、学生个人画像、共性错因统计和分层练习。

系统定位为教师决策辅助工具，不代替教师作出最终成绩和教学评价。项目聚焦一个学科和一个学段，即初中数学，不扩展为全学科智慧校园平台。

## 2. 背景与现实需求

中小学教师在完成日常批改后，仍需统计共性错题、分析知识点薄弱情况、判断典型错因并准备差异化练习。这些工作重复度较高，传统成绩表又难以呈现学生在具体知识点和错误类型上的连续变化。

教育部发布的数字化赋能教师发展行动提出，基于大模型研发教师智能助手，为教研备课、作业管理、学情分析和学生评价等工作提供支持。教育数字化相关意见同时强调人工智能安全、数据安全和个人信息保护。因此，本项目选择“规则批改、大模型建议、教师审核、学情分析”的人机协同路线。

## 3. 建设目标

1. 建立班级、学生、初中数学知识点、题目、作业和作答的基础数据体系。
2. 对选择题和填空题实施确定性规则批改。
3. 对解答题生成逐评分点的建议得分、证据、错因标签和反馈建议。
4. 建立教师审核机制，确保未经确认的 AI 结果不进入正式成绩和学情统计。
5. 基于确认后的数据生成班级和学生两个层级的学情分析。
6. 根据薄弱知识点辅助生成基础、巩固、提高三档练习，并由教师审核后导出。
7. 通过真实脱敏样本评估 AI 建议的准确性、一致性、效率和教师可接受度。

## 4. 非目标

首版不实现以下内容：

- 拍照 OCR、手写公式识别和试卷版面还原；
- 学生端在线考试、家长端和家校沟通；
- 排课、考勤、校园通知等综合校务功能；
- 覆盖语文、英语等其他学科；
- 自建或微调大模型；
- RAG、向量数据库和复杂知识图谱；
- 由 AI 直接发布最终成绩或未经教师审核的练习。

## 5. 用户与权限

### 5.1 教师

- 管理本人负责的班级和学生；
- 维护题目、答案、评分细则和知识点；
- 创建作业并导入学生作答；
- 查看并审核 AI 建议；
- 查看学情分析并生成分层练习；
- 导出作业分析与练习材料。

教师只能访问自己负责的班级及其关联数据。

### 5.2 管理员

- 管理教师账号；
- 配置启用的模型服务；
- 查看脱敏后的任务状态与系统日志。

管理员端不扩展为校级教学管理平台。

## 6. 核心业务流程

```text
创建班级和学生
      ↓
维护知识点、题目、标准答案和评分细则
      ↓
创建作业并导入学生答案
      ↓
客观题规则批改 ──────┐
解答题 AI 建议批改 ──┤
                      ↓
                 教师审核
                      ↓
            正式成绩与错因数据
                      ↓
       学情画像、班级讲评与分层练习
```

只有教师确认后的结果才能进入正式统计。教师修改 AI 建议时，系统同时保留原始结果、修改后结果、修改时间和修改原因。

## 7. 功能设计

### 7.1 工作台

展示待审核作业、异常批改任务、近期班级平均分、薄弱知识点和高频错因。

### 7.2 班级与学生

支持班级、学生的增删改查和 Excel 批量导入。系统内部使用学生编号关联数据，调用模型时不传递姓名、学号和班级名称。

### 7.3 知识点与题库

维护初中数学知识点树。每道题记录题型、难度、所属知识点、标准答案、解析、总分和分步评分细则。一个题目可关联一个主要知识点和多个次要知识点，统计掌握率时以主要知识点为准，避免重复计数。

### 7.4 作业管理

教师从题库选择题目组成作业，通过统一模板导入学生答案。系统展示导入校验结果、批改进度、失败原因和待审核数量。

### 7.5 批改审核

审核页同时展示题目、标准答案、评分细则、学生答案、AI 建议得分、逐项依据、错因标签和反馈建议。教师可以接受、修改或驳回建议。

### 7.6 学情分析

提供以下分析结果：

- 班级成绩分布；
- 各知识点掌握率；
- 高频错因排行；
- 学生个人薄弱知识点；
- 同一知识点在历次作业中的变化趋势。

知识点掌握率统一按“该知识点确认得分之和 / 该知识点可得总分”计算，并显示样本作答数量，防止小样本被误读。

### 7.7 分层练习

教师选择薄弱知识点、题目数量和难度层级，系统调用大模型生成基础、巩固、提高三档候选题及答案解析。候选内容必须经过教师审核，审核后才能导出为 Word 或 PDF。

## 8. 技术架构

采用前后端分离的模块化单体架构，不引入微服务。

```text
Vue 3 教师端
    ↓ REST API
Spring Boot 业务后端
    ├─ 用户与权限模块
    ├─ 班级与学生模块
    ├─ 知识点与题库模块
    ├─ 作业与批改模块
    ├─ 学情统计模块
    ├─ 分层练习模块
    └─ AI 任务编排模块
    ↓                ↓
  MySQL          大模型 API
```

建议技术栈：

- 前端：Vue 3、TypeScript、Element Plus、ECharts、MathJax；
- 后端：Spring Boot、Spring JDBC、Spring Security 与 JWT；
- 数据库：MySQL；
- 文件处理：EasyExcel，Word/PDF 导出采用成熟的 Java 文档库；
- AI 接入：后端统一模型接口适配层；
- 实验统计：Python 离线评测脚本，不部署独立 Python 服务。

## 9. AI 方案

### 9.1 技术路线

系统采用“确定性规则 + 大模型 API + 教师审核”的混合方案：

- 选择题、填空题由程序根据标准答案批改；
- 解答题由大模型按评分细则给出建议；
- 大模型不接收学生身份信息；
- 大模型输出必须经过格式和业务规则校验；
- 最终结果由教师确认。

项目不使用 RAG。知识点、标准答案、评分细则和错因标签均由 MySQL 管理，并在单次分析时直接提供给模型。

### 9.2 模型输入

每次解答题分析至少包含：

- 题目内容；
- 主要知识点；
- 总分；
- 标准答案；
- 分步评分细则；
- 匿名学生答案；
- 允许选择的错因标签集合。

### 9.3 结构化输出

模型必须返回固定 JSON 结构，包括：

- 建议总分；
- 每个评分点的得分与证据；
- 错因标签；
- 给教师查看的分析说明；
- 给学生使用的反馈建议；
- 是否需要重点人工复核。

后端通过 JSON Schema 和业务规则进行校验，包括分数范围、评分点总和、标签合法性和必填字段。校验失败时不生成正式结果，任务进入重试或人工处理状态。

### 9.4 稳定性控制

- 模型参数使用较低温度；
- 保存提示词模板版本、模型标识和原始结构化响应；
- 对超时、限流和临时网络错误实施有限次数的指数退避重试；
- 对格式错误可执行一次格式修复重试；
- 达到重试上限后转为人工处理，禁止无限重试；
- 同一作答和同一提示词版本设置幂等键，避免重复计费和重复入库。

## 10. 核心数据实体

- User：用户与角色；
- Teacher：教师资料；
- Class：班级；
- Student：学生及匿名编号；
- KnowledgePoint：知识点及父子关系；
- Question：题目、题型、难度与答案；
- QuestionKnowledgePoint：题目与知识点关联；
- RubricItem：题目评分点；
- Assignment：作业；
- AssignmentQuestion：作业题目及顺序；
- Submission：学生作业提交；
- StudentAnswer：单题作答；
- AiGradingTask：AI 任务状态与重试信息；
- AiGradingResult：AI 原始建议；
- TeacherReview：教师确认结果与修改记录；
- MasteryRecord：按作业形成的知识点掌握记录；
- GeneratedExercise：分层练习及审核状态。

正式成绩以 TeacherReview 为准，AiGradingResult 仅作为辅助证据，避免数据口径混乱。

## 11. 异常处理

- Excel 缺列、格式错误、学生编号不存在时，返回具体行号和原因；存在结构性错误时整批拒绝，避免部分导入造成数据不一致。
- 模型超时、限流、不可用或输出格式错误时，任务保持可重试状态，不产生正式成绩。
- AI 建议分越界、评分点之和不一致或错因标签非法时，后端拒绝该结果。
- 作答重复提交时，通过唯一约束和幂等键避免重复批改。
- 统计任务失败不影响已确认成绩，教师可重新触发统计。
- 导出失败时保留已审核数据，并向教师返回可行动的错误信息。

## 12. 安全与隐私

- 实施身份认证和基于角色、数据归属的权限校验；
- 向大模型发送数据前移除姓名、学号、班级名称等身份字段；
- API 密钥仅保存在后端环境变量或安全配置中，不进入前端、代码仓库和日志；
- 日志不记录密钥、完整学生答案和个人身份信息；
- 对上传文件实施扩展名、MIME、大小和内容结构校验；
- 对用户输入进行服务端校验，数据库访问使用参数绑定；
- 重要删除操作二次确认，成绩和审核记录优先软删除并保留审计信息；
- 演示和论文仅使用脱敏数据。

## 13. 测试与实验设计

### 13.1 软件测试

- 单元测试：客观题判分、分数汇总、掌握率、权限和校验规则；
- 集成测试：作业导入、批改任务状态流转、教师审核和统计更新；
- 接口测试：认证、越权访问、重复提交、错误参数和模型异常；
- 前端测试：正常、加载、空数据、错误、禁用和审核状态；
- 人工验收：完整执行一次“导入—批改—审核—分析—生成练习—导出”流程。

### 13.2 AI 效果实验

由合作教师对一批脱敏的初中数学解答题作答进行独立评分和错因标注，作为人工基准。建议使用 100 至 300 份作答，最终样本量根据可获得数据在开题时固定并如实说明。

评估指标包括：

- AI 建议分与教师评分的平均绝对误差；
- 在预设允许误差内的评分一致率；
- 错因标签的准确率、精确率、召回率和 F1；
- AI 建议被教师直接接受、修改和驳回的比例；
- 无系统与使用系统两种条件下的平均处理耗时；
- 教师对可用性、可信度和解释性的问卷评价。

在正式实验前固定评分细则、提示词版本、模型版本和采样参数。测试样本不得用于反复调整提示词后再作为最终测试集，避免结果偏高。

## 14. 验收标准

1. 完成班级、学生、知识点、题库、作业、作答导入、批改审核、学情分析和分层练习的完整闭环。
2. 客观题批改、分数汇总和知识点掌握率具有自动化测试证据。
3. 未经教师审核的 AI 结果不能进入正式成绩、统计和对外导出。
4. 所有 AI 建议均可追溯到题目、评分细则、提示词版本、模型标识和教师审核记录。
5. 模型调用失败时，业务数据不丢失，任务可以重试或转人工处理。
6. 至少使用一批脱敏且经教师确认的数据完成效果实验。
7. 最终论文提供可复现的实验方法、指标、图表、结果和局限性说明。

## 15. 主要风险与控制措施

| 风险 | 控制措施 |
|---|---|
| 大模型数学评分不稳定 | 分步评分细则、低温度、结构校验、教师终审 |
| API 不可用或费用超出预期 | 批量任务队列、有限重试、幂等控制、可替换模型适配层 |
| 真实样本不足 | 尽早与合作教师确定脱敏格式和最低样本量 |
| 学生隐私泄露 | 匿名编号、最小化上传字段、日志脱敏、权限隔离 |
| 功能范围膨胀 | 坚持初中数学、教师端、Excel 导入和非 RAG 范围 |
| 实验结果偏高或不可复现 | 固定测试集、提示词版本、模型参数和评价方法 |

## 16. 建议实施阶段

1. 基础数据与权限：教师、班级、学生、知识点和题库。
2. 作业闭环：组卷、作答导入、客观题批改和教师确认。
3. AI 批改：解答题结构化建议、任务重试和审核追踪。
4. 学情分析：知识点掌握率、错因统计和趋势图。
5. 分层练习：候选题生成、教师审核和导出。
6. 测试与实验：软件测试、教师实验、数据分析和论文材料。

每个阶段均应先完成可运行、可验证的纵向闭环，再进入下一阶段。
